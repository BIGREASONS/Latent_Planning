# Data Generation Audit

Target: `scripts/generate_countdown_dataset.py` + `data/*.jsonl` + the 5000/500/1000/500 trajectory pickles.

## How the generator actually works (read the code)

`generate_countdown_problem()` does **not** generate a Countdown problem and solve it. It does the reverse:
1. Builds a `pool` of 6 numbers.
2. Picks a random `num_ops ∈ [2,5]`, samples `num_ops+1` numbers.
3. Walks forward applying **random** ops (`+ - *`, never `/`), chaining the running value.
4. Sets `target = final running value`.

So the "solution" is the generation trace itself. **This is solution-by-construction, not search.** Consequences:

- There is no guarantee the stated solution is the *only* or *canonical* one, and no verification that the target is reachable by any standard Countdown rule set (operand-use-once is not enforced on the running value).
- `arg1` of the running chain reuses the previous result, and the first operand is a pool number — the "available numbers" semantics needed for symbolic-state labeling are ill-defined.

## Quantitative findings (reproduced)

Simulated the **default protocol** (1000 train / 100 test, independent calls, no dedup, no seed), 20 trials:

| Metric | Result |
|---|---|
| Identical (numbers,target) test problems also in train | mean **0.65**, max **2** |
| Identical numbers-multiset test problem in train (out of 100) | mean **31.4**, max **44** |
| Shared individual reasoning steps train∩test | mean **150**, max **169** |
| Number-multiset collision rate (within 1200 draws) | **27.8%** |
| Exact (numbers,target,cot) duplicate rate | ~0.0% (cot makes rows unique) |

## Answers to required questions

- **Are train/test splits truly disjoint?** No. 24 shared (target,numbers) problems train∩test in the real data; 12 train∩val. Splits are generated by independent random draws with no dedup and no seed, so disjointness is accidental, not enforced.
- **Can duplicate problems occur?** Yes — 1.1% within train; 27.8% number-multiset collision rate.
- **Can symbolic states leak across splits?** Yes — identical (target, numbers) states appear in both train and test (24 cases), and far more share partial state.
- **Can action sequences leak?** Yes — ~150 individual reasoning steps shared train∩test per draw.
- **Can solutions be memorized?** The `cot` string is near-unique (so exact-row dedup looks clean), but the underlying *problems* and *steps* are not, so a model can memorize sub-trajectory patterns that recur across splits.

## Verdict

The generator is **not fit for a planning benchmark**. It conflates problem with solution, cannot produce division, produces astronomically large unbounded targets (anti-Countdown), enforces no operand-use-once invariant, is unseeded, and performs no cross-split deduplication. Leakage is real and uncontrolled, though numerically modest at current scale. The clean-looking exact-duplicate rate is an **illusion created by the free-text `cot` field**, which masks problem-level and step-level collisions.
